# WB 运营分析与可售链路

用于“店铺指标、运营分析、浏览/加购/订单、商品问题、可售检查”请求。只读默认，不得因分析直接修改价格、广告、属性或库存。

## 数据口径

- 商品卡总数：使用 `POST https://seller-analytics-api.wildberries.ru/api/analytics/v3/sales-funnel/products` 的全量 `data.products`；设置 `limit: 1000, offset: 0`，不要把 Content 单页或价格商品数当总卡数。
- 漏斗：`selectedPeriod` 与等长 `pastPeriod`；使用 IANA 时区。字段包括 `openCount`、`cartCount`、`orderCount`、`buyoutCount`、`addToWishlist`、`conversions`、`product.stocks`。该接口小时级更新，限流为每卖家每分钟 3 次、间隔 20 秒。
- 新卡：上架 1–2 天时低曝光与零订单通常只应标记为冷启动，先观察 3–7 天或做小预算测试；不能仅凭低曝光断言属性错误。
- 搜索诊断：只有需要判断搜索词、位置和筛选属性匹配时，再读取官方搜索查询接口；漏斗数据本身不能证明某个商品参数错误。

## 运营报告

将每次读取结果写入 `E:\电商运营\01平台资料\01WB\<category>\04运营资料\`，使用时间戳文件名。报告至少包含：查询时间、地区/时区、数据周期、接口状态、商品总卡数口径、店铺与类目汇总、重点 SKU 漏斗、库存口径、判断与未执行的建议。不要写入令牌。

## 有加购无订单的优先检查

按顺序核查：

1. 内容卡存在，错误卡列表不含 nmID；图片、尺寸、毛重有效。
2. 价格与折扣 API 已读回；明确 API 币种与前台地区币种，不能混用。
3. `GET /api/v3/warehouses` 返回活动仓库；对每个独立条码执行 `POST /api/v3/stocks/{warehouseId}` 并要求 `amount > 0`。
4. 用公开前台页在指定地区检查商品标题、买按钮和预计送达日期；不加入购物车、不下单。
5. 若硬条件都通过但加购未转订单，优先把地区到手价、配送时效、支付/信任要素列为待验证摩擦；不要先批量改属性。

## 结论表达

区分“已验证事实”“合理推断”“待验证”。样本很小时，`cartCount / openCount` 可能大于 100%，不得将该比率当作稳定转化率。
