# WB 固定早间日报模板

除非用户明确要求调整，所有早间日报必须稳定按以下顺序输出；不得临时省略类目拆分，也不得把不同数据口径混为同一指标。

1. **快照信息与口径**：本次抓取时间、上一有效快照时间、滚动统计周期、时区、接口状态。
2. **店铺总览对比**：内容卡总数、纳入 Analytics 漏斗的商品卡、浏览、加购、订单、买退、收藏、卖家仓库存、WB 仓库存、仓库数、广告活动、待回复评价/问题、FBS 订单；每项必须列出“本次 / 上次 / 变化”。
3. **类目指标对比**：每个类目单独一行，至少列出内容卡、Analytics 漏斗卡、浏览、加购、订单、收藏、卖家仓库存、WB 仓库存；列名只显示指标名，每个单元格以“本次数值（带正负号的变化）”表达，例如 `142（+0）`，不展示上次绝对值。类目内容卡以 Content 全量分页结果为准；流量和漏斗指标以 Analytics v3 为准。
4. **重点 SKU 漏斗**：按加购数排序，展示 SKU、nmID、浏览、加购、订单及与上次快照的变化（前提是上次逐 SKU 快照可用）。
5. **异常提醒**：仅展示零库存/低库存 SKU、加购无订单、订单与库存或 FBS 链路异常；无异常时用一行说明，不展开空表。
6. **可行动机会**：优先列出加购无订单的重点 SKU；建议只包含下一步可验证动作，不直接修改价格、广告、库存或商品内容。
7. **广告与促销状态**：广告 fullstats 仅在存在在投活动时展示曝光、点击、花费、加购、订单和 ROI；促销日历仅展示未来 7 天可报名或临近截止活动。未接入或无活动时简洁标注，不杜撰数据。
8. **已验证事实、合理推断、待验证项**：明确区分。不得把 Analytics 漏斗未覆盖的卡误报为删除或下架。
9. **数据状态**：各接口 HTTP 状态、未执行的写操作，以及快照和报告文件路径。

## 比较规则

- 默认比较“本次抓取时点”与“上一有效早间快照”，不是自然日累计。
- 滚动窗口随日期移动，指标变化不能直接解释为当天新增量。
- 每份快照必须保存总览、逐类目汇总、内容卡口径和 Analytics 漏斗口径，供下一次日报复用。
